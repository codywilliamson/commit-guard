# commit-guard

`commit-guard` checks Conventional Commit headers with one small native checker. The same checker version and `.commit-guard.json` policy run in local Git hooks and GitHub Actions. A repository-specific header limit is optional; the default is unlimited.

## Install the hooks

Run the installer from the repository root. It downloads a release asset and verifies its SHA-256 manifest before installing the workflow, policy file, and native `commit-msg` and `pre-push` hooks.

```bash
curl -fsSL https://raw.githubusercontent.com/codywilliamson/commit-guard/main/install.sh | bash
```

On Windows PowerShell 5.1 or newer:

```powershell
irm https://raw.githubusercontent.com/codywilliamson/commit-guard/main/install.ps1 | iex
```

Use `--ci-only` or `-CIOnly` when you want the workflow and policy without local hooks. Pin the bootstrap download with the exact release tag in `COMMIT_GUARD_REF`:

```bash
curl -fsSL https://raw.githubusercontent.com/codywilliamson/commit-guard/main/install.sh | COMMIT_GUARD_REF=v0.3.0 bash
```

The installer adds a repository-local Git alias, without changing your global `PATH`:

```bash
git commit-guard status
git commit-guard sync
git commit-guard uninstall
```

Clean installs put native hook executables in Git's private hooks directory to avoid shell startup overhead. Existing custom shell hooks keep a managed block and backups. The installer replaces exact validators generated by older versions. Shared hooks outside the repository and non-shell hooks require manual integration. It creates `.commit-guard.json` only when the file does not already exist.

See [configuration.md](docs/configuration.md) for the strict JSON policy reference.

## Use the action directly

The direct action needs no checkout and reads commit metadata and policy through the GitHub API. Pin it to a release or full commit SHA:

```yaml
name: Commit Guard

on:
  pull_request:
    types: [opened, synchronize, reopened, edited]
  push:
    branches: [main, master]
  merge_group:
    types: [checks_requested]

permissions:
  contents: read
  pull-requests: read

jobs:
  commit-guard:
    runs-on: ubuntu-latest
    steps:
      - uses: codywilliamson/commit-guard@v0.3.0
        with:
          token: ${{ github.token }}
```

The action defaults to commit mode. `mode: title` checks the pull request title and continues to check commit ranges on pushes. `mode: smart` is retained as a compatibility alias for commit mode and does not skip bot commits or fall back to titles. Workflow dispatch runs require explicit `from` and `to` inputs. The action reads the fixed `.commit-guard.json` path so its policy matches local checks.

The action downloads one platform binary from the release and validates `SHA256SUMS`. It supports Linux, macOS, and Windows on amd64 and arm64. The optional `binary` input is intended for repository CI fixtures and tests that already built a checker.

## Keep a legacy reusable workflow

Existing callers can continue to use the reusable wrapper while migrating:

```yaml
jobs:
  commit-guard:
    uses: codywilliamson/commit-guard/.github/workflows/commitlint.yml@v0.3.0
    with:
      pr-mode: commits
    permissions:
      contents: read
```

The wrapper accepts its default `conventional` configuration and the `pr-mode` values `commits`, `title`, and `smart`. Unsupported legacy customization fails explicitly. The installer preserves existing jobs when it updates an older wrapper reference and backs up the previous workflow.

## Manage an installed checker

There is no update lookup during a commit or pre-push check. Dependabot watches the pinned GitHub Action reference in the workflow and can propose a release update. After pulling an accepted update, the local hook tells you to synchronize if the required checker is missing:

```bash
git commit-guard sync
```

`sync` downloads and verifies the exact repository-pinned release, or activates an already cached copy. It never selects the latest release implicitly. The downloaded native executable's `install --ref` accepts an exact release tag such as `v0.3.0` or a full commit SHA. It also accepts `--mode commits|title`, `--ci-only`, and `--no-updates`. The bootstrap scripts retain the legacy `--pr-mode` or `-PRMode` spelling as an alias for the mode selection.

## Commit format

```text
type(scope): description
```

The checker accepts the standard types listed in [configuration.md](docs/configuration.md), applies case-insensitive type matching, and reports malformed headers without executing repository code. It does not load JavaScript commitlint configuration.

## Requirements

- Git for local hooks
- GitHub Actions with `contents: read` for the direct action
- No Node or package manager for native checking
